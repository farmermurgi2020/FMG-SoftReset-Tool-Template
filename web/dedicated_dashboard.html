FMG Soft Reset Tool — Dedicated

Local settings page. Settings are saved to this PC and can be synced to a private GitHub repository. SFTP secrets are sent encrypted to GitHub and are never written to the local settings file.

GitHub destination

For Sync and Run dry-run, create a fine-grained token limited to this private repository with Contents, Workflows, Actions, and Secrets write permissions. The page keeps it in memory only. Never paste it into chat or a config file.

Pine Hosting SFTP and save paths

SFTP credentials (optional on later syncs)

Use the Pine Hosting SFTP password, or a private key if SSH key login is configured. The private key and passphrase are optional. The known_hosts line is also optional: if supplied, the worker verifies the server against it; if blank, it accepts an unpinned host key. Blank fields keep previously saved GitHub secrets unchanged.

Reset and schedule

For each kind of data, choose what a reset does. "Keep protected zones" keeps whatever overlaps your protected zones and safehouses (8×8-tile map chunks; 256×256-tile population cells). "Reset everything" ignores the zones for that kind of data. "Don't touch" leaves it as it is.

zpop_ids.bin and zpop_virtual.bin are always kept because they cannot be split by location.

The worker does not check whether the server is running. Scheduled apply relies on your Pine Hosting power schedule stopping the server before the reset time and starting it after the window. Keep scheduled runs on dry run until a manual apply and rollback have been tested.

Cron-job keys

GitHub's own schedule can start late, skip runs, or never fire for some accounts. cron-job.org (free) can instead press the workflow's "Run workflow" button at your reset time. Sync then creates or updates the cron-job.org job with the day, time and timezone set above, so you don't need to set it up on their site. A run started this way still checks the reset date, time, allowed lateness and Pine Hosting window, and does nothing outside them.

The GitHub token here is stored inside the cron-job.org job, so give it the least access: only this repository, with Actions: Read and write and nothing else. Both keys are kept in memory for this page only and cleared after a successful sync. Leave them blank on later syncs: a blank cron-job.org key leaves the job untouched, and a blank GitHub token keeps the token already stored in the job. Choosing GitHub's built-in schedule with the cron-job.org key entered pauses the cron-job.org job so the reset cannot run twice.

Ready.

Reset now / roll back

Stop the server in the Pine Hosting panel first and wait until it shows offline. Apply resets every unprotected map chunk; the original map is kept in a single softreset.rollback-… folder in the save (older ones are deleted). Rollback swaps that folder back in, and the replaced state becomes the new rollback folder, so a rollback can itself be undone.

Hard Reset (Player Data only)

Removes every character so players start fresh with a new one, and restarts the world at day 1 (world clock, vegetation growth and the radio/TV schedule). On the next server start, the FMGResetTool mod also removes all safehouses and factions. Kept: map chunks (buildings, loot, player-built bases), zombie and animal population, vehicles, accounts, passwords and admin roles. Run a soft reset first if you want the map refreshed too: once safehouses are gone they no longer protect anything.

Stop the server in the Pine Hosting panel first and wait until it shows offline. The removed files are moved into a hardreset.rollback-… folder in the save (with copies of map_meta.bin and global_mod_data.bin), so Undo latest hard reset brings the characters, day count, safehouses, factions and Knox Claim claims back. Building changes and every mod's saved data changed after the hard reset are lost on undo. The server must run the updated FMGResetTool mod (with FMGHardReset.lua) for safehouses and factions to be removed.
